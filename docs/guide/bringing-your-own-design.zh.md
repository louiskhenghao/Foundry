# 带上你自己的设计稿

你已经在 Claude Design、Figma 里或者亲手把界面设计好了，想让结果长成它的样子，而不是 agent 自己想象出来的样子。这一页讲怎样把设计稿交给一个 goal，以及 Foundry 会拿它做什么。

## 附上文件，不要只给链接

Claude、Figma、Canva 或 Framer 页面的链接当不了设计稿。那些页面要登录，给你的 goal 干活的会话打不开它们；一个只有这种链接的 goal，拿到的会是 agent 自己的设计。描述或链接附件一指向这些工具，New goal 表单就会说明这一点；从这样的 goal 写出来的 Brief 会用一个阻塞问题请你附上导出件，或者选择不用设计稿。

改成从工具里导出：一个 HTML 文件或一个 zip（Claude Design 和 Figma 给的就是这个），或者每个页面的截图。在描述下面用 **Files** 附上，或者拖进来、粘贴进来。zip 一到就会解开，会话能读到里面的每个文件。

## 设计参考

图片、HTML 页面或 zip 附到代码 goal 上时会被标为 **Design reference**（其他类型的 goal 把图片当参考或 Subject；要标的话点一下小标签就行）。附件上的小标签就是它；点一下，文件就变回普通参考；再点一下，又成为设计稿。文档和链接不能当设计稿。你也可以之后在 goal 页面附上设计稿，然后在 Brief 页面按 **Re-run Clarify**，让 Brief 按它重写。

设计参考对这个 goal 就是法律：它画了什么，就照着做什么——页面、区块、布局、文案、颜色、字体、组件，以及它画出来的状态。HTML 导出件会被当作源材料来读：会话把它的标记、样式和 token 移植进你的项目，而不是看着图猜。

## Brief 会拿它做什么

附了设计稿之后，Clarifier 不再提几个风格方向让你选。Brief 只显示一张卡片，**From your design**，已经选中：那是 Clarifier 从你的文件里读出来的颜色和字体。工人们遵循的是设计稿本身，不是这张卡片。

Clarifier 会打开每个设计文件，把它的清单（每个页面、页面上的区块和组件、画出来的状态、文案）写进给 planner 的笔记，并为设计稿画出的每个页面加一条 goal 级别的检查，名为 **Matches the design: &lt;page&gt;**，由 goal reviewer 来判。设计稿没画、但工作需要的东西——空列表、加载中或出错的状态、手机宽度——会列成假设，写明会按你设计稿的语言怎么做；在 Brief 页面上随便改。planner 给每个页面一个自己的任务，写明它遵循的设计文件，并附一条对照它的检查。

## 工人会拿它做什么

每个做页面的工人都会在任务之后、任何风格方向之前看到设计参考，并附带规则：风格方向或设计技能与设计稿有出入时，设计稿说了算。goal 的设计技能（见[设置说明](./settings.zh.md#skills)）仍然在，用来补设计稿没定的部分：没画出来的状态、页面在手机上的表现、无障碍、动效。它用你设计稿的语言去补这些空缺，从不重新选方向。

## 每个 goal 自己的设计技能

一个 goal 的 UI 任务遵循哪套设计技能，来自 Settings → Skills → **Design skills**。代码 goal 可以在 New goal 表单上、goal 类型下面另选一套：**Design skills** 列出各个包，Settings 的包排在前面，没为你的编码 agent 安装的会标出来。命令行里 `foundry goal new … --design-pack bencium` 效果一样。附了设计稿之后，不管选哪个包，它都只补设计稿没定的部分。

## 结果仍有出入时

把结果和你的设计稿逐页对照。有出入的地方，用 **Adjust the result**（beta，Settings → Beta）说明是哪个页面、该对上哪个设计文件；或者用一条 Decision 来 **Revise** Brief。两者都会把你的话带给会话，设计参考也一直留在 goal 上供它们读。
