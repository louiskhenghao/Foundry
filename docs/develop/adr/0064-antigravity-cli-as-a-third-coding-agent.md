# ADR-0064: The Antigravity CLI as a third coding agent

**Status:** accepted · 2026-10-21 · amends [ADR-0017](0017-fixed-goal-providers-and-independent-accounts.md) (fixed goal providers)

## Context

The Gemini CLI was retired for individual accounts on 2026-06-18; Google's successor is the Antigravity CLI (`agy`). It has a documented print mode: newline-delimited JSON in and out (`--input-format stream-json`, `--output-format stream-json`), structured output through `--json-schema`, a conversation resumed by id (`--conversation`), three effort levels, hooks read from a workspace file, and token counts rather than dollar costs. Foundry's roadmap asked for a third coding agent beside Claude Code and Codex. Nothing of agy runs on the machine this was built on: the adapter follows the CLI's documentation and is tested against a stand-in that behaves as documented.

## Decision

A third provider, `agy`, beside `claude` and `codex`, fixed per goal as ADR-0017 fixes the others. The shared enum `AgentProvider` lives in core (`schema/provider.ts`) with two helpers, `reportsDollars` and `agentsFolder`, so that engine code says what it means (no dollar costs; the `.agents` folder) instead of naming Codex at every such place.

The adapter (`AgyCliRunner`, runner package) runs one turn per session: the prompt goes down stdin as a `user` event with the role text ahead of it (the CLI has no developer-instructions switch), `--json-schema` carries the role's output schema, `--conversation` resumes, `--effort` takes Foundry's effort words mapped to low, medium and high, `--dangerously-skip-permissions` leaves approvals to Foundry's own guard, `--disable-slash-commands` keeps a prompt from being read as a command, and `--print-timeout` sits a minute past Foundry's own deadline. Answers stream as fragments the decoder joins per step; a tool step carries its call and output in one record.

Foundry's guard is a `PreToolUse` hook and its canary a `SessionStart` hook in the workspace's `.agents/hooks.json`, added for the run under a key of the session's own and taken out after it; the person's entries stay, the file goes when the last Foundry entry does and there was none before, and the path is git-excluded so a worker's commit never carries it. The guard keeps the boundary (no push, PR, deploy or publish), the read-only roles on the file tools, and the tool-call allowance that stands in for a turn cap. A session whose canary never appears is stopped before it works, as a Codex session is.

Antigravity reports tokens, so its goals keep time, attempt and concurrency limits and never a USD budget; calibration, reports and estimates in dollars leave them out. One model serves every role of a goal (`models.agyModel`, `agy-default` following the CLI's own setting) at one effort (`models.agyEffort`); `agy models` fills the registry; there are no presets and no fallback order, since the CLI refuses an unknown model outright. The account's state is read with a read-only `agy -p /usage --output-format json`; signing in happens in a terminal (the CLI opens the browser) and signing out inside agy, neither driven by Foundry. Skills Foundry places in a project's `.agents/skills` (workflow suites, the Learnings notebook) are read as Codex reads them; the shared `~/.agents/skills` is the user-level inventory. Plugins and MCP servers are managed in agy itself: Foundry keeps no MCP allowlist for it and `strictMcp` is not enforced; autoskills, the `skills` CLI updates, skill telemetry and external session history do not apply. A profile is `FOUNDRY_PROVIDER=agy` with `data-agy/`, `FOUNDRY_AGY_BIN` and `FOUNDRY_AGY_MODEL`; Doctor's rows are `agy-bin`, `agy-auth` and `agy-config`.

## Consequences

The protocol facts come from the CLI's documentation, not from a run: the payload of `/usage`, the JSON of `agy models`, the field names of a hook's input, and whether print mode loads workspace hooks are read defensively and reported by Doctor and by the session's own error. The first real session to try: the canary must appear (else every session fails closed), structured output must land in `structured_output`, and denied actions must surface. Two Foundry sessions in one folder run each other's guards; a guard only denies, so the stricter policy wins. Read-only roles are enforced on the file tools only: a shell write slips past the guard, where Codex has an operating-system sandbox (agy's `--sandbox` is undocumented in its effect and is not used). The CLI's known defects, an empty SUCCESS and a dropped stream, become failed sessions the attempt loop retries.
