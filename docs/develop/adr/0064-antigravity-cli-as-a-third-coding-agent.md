# ADR-0064: The Antigravity CLI as a third coding agent

**Status:** accepted · 2026-10-21 · amends [ADR-0017](0017-fixed-goal-providers-and-independent-accounts.md) (fixed goal providers)

## Context

The Gemini CLI was retired for individual accounts on 2026-06-18; Google's successor is the Antigravity CLI (`agy`). It has a documented print mode: newline-delimited JSON in and out (`--input-format stream-json`, `--output-format stream-json`), structured output through `--json-schema`, a conversation resumed by id (`--conversation`), effort levels, hooks read from a workspace file, and token counts rather than dollar costs. Foundry's roadmap asked for a third coding agent beside Claude Code and Codex. The adapter was written from the CLI's documentation and then checked against agy 1.4.4 on a signed-in account, which corrected it in four places (see Consequences); its tests use a stand-in that behaves the way that CLI does.

## Decision

A third provider, `agy`, beside `claude` and `codex`, fixed per goal as ADR-0017 fixes the others. The shared enum `AgentProvider` lives in core (`schema/provider.ts`) with two helpers, `reportsDollars` and `agentsFolder`, so that engine code says what it means (no dollar costs; the `.agents` folder) instead of naming Codex at every such place.

The adapter (`AgyCliRunner`, runner package) runs one turn per session: the prompt goes down stdin as a `user` event with the role text ahead of it (the CLI has no developer-instructions switch), `--json-schema` carries the role's output schema, `--conversation` resumes, `--effort` takes Foundry's effort words mapped to low, medium, high, xhigh and max, `--dangerously-skip-permissions` leaves approvals to Foundry's own guard, `--disable-slash-commands` keeps a prompt from being read as a command, and `--print-timeout` sits a minute past Foundry's own deadline. Answers stream as fragments the decoder joins per step; a tool step carries its call and output in one record.

Foundry's guard is a `PreToolUse` hook and its canary a `SessionStart` and `PreInvocation` hook in the workspace's `.agents/hooks.json`, added for the run under a key of the session's own and taken out after it; the person's entries stay, the file goes when the last Foundry entry does and there was none before, and the path is git-excluded so a worker's commit never carries it. The guard reads the call as `toolCall { name, args }`, keeps the boundary on `run_command` (no push, PR, deploy or publish), the read-only roles on the file tools (`write_to_file`, `replace_file_content`, `multi_replace_file_content`, `sed_file`, `notebook_edit`), and the tool-call allowance that stands in for a turn cap (three calls per turn of the cap, since agy calls a tool for every file it reads); it refuses agy's own subagents, since Foundry runs the roles, and always lets `finish` through, the tool that hands over an answer under `--json-schema`. A session whose canary never appears is stopped before it works, as a Codex session is.

Antigravity reports tokens, so its goals keep time, attempt and concurrency limits and never a USD budget; calibration, reports and estimates in dollars leave them out. One model serves every role of a goal (`models.agyModel`, `agy-default` following the CLI's own setting) at one effort (`models.agyEffort`: low, medium, high, xhigh or max); the `slug<TAB>label` lines of `agy models` fill the registry; there are no presets and no fallback order, since the CLI refuses an unknown model outright. The account's state is read with a read-only `agy -p /usage --output-format json`; signing in happens in a terminal (the CLI opens the browser) and signing out inside agy, neither driven by Foundry. agy reads skills only from a workspace's `.agents/skills`, never from `~/.agents/skills`, so Foundry's Antigravity skill store is the shared `~/.agents/skills` (Codex and the community `skills` CLI read it as well), managed from Setup and Extensions like the other agents' stores, and before each session the installed skills a role may follow are linked into the workspace by name, git-excluded, beside the workflow suite's links and the Learnings notebook; autoskills writes that layout through its Codex agent. Plugins and MCP servers are managed in agy itself: Foundry installs no plugin for it (so no text-to-cad), keeps no MCP allowlist, does not enforce `strictMcp`, and its MCP routes refuse Antigravity; skill telemetry and external session history do not apply. The same `/usage` command gives the account's quota, one weekly limit per group of models, which the Usage page shows. A profile is `FOUNDRY_PROVIDER=agy` with `data-agy/`, `FOUNDRY_AGY_BIN` and `FOUNDRY_AGY_MODEL`; Doctor's rows are `agy-bin`, `agy-auth` and `agy-config`.

## Consequences

Checked against agy 1.4.4 on 2026-10-22, the documentation was wrong or silent on four points the adapter now follows. A session event (`SessionStart`, `PreInvocation`) takes its handlers as they are and a tool event takes them under a matcher; one entry spelled the other way makes the CLI drop the whole hooks file, and then no hook runs at all. A resumed conversation fires no `SessionStart`, so the canary is written on `PreInvocation` too. The `PreToolUse` input names the call `toolCall { name, args }` (`run_command` with `CommandLine`). Under `--json-schema` the answer comes through a `finish` tool, which a session without tools must still be allowed, or the model retries until its budget is gone. Besides, `agy models` prints tab-separated lines and refuses `--output-format`, and `/usage` answers in JSON with weekly quota buckets but no account identity, so Accounts shows the account as signed in without a name. Four real turns through the adapter then passed: structured output, a worker's `git push` refused by the guard while `cat` ran, a resumed conversation that remembered its first answer, and a read-only role refused a file write; the hooks file was gone afterwards and the tree clean. The regression set's `fix-failing-test` case (ADR-0062) then ran end to end on agy and passed: Clarify and its planner, an engine-approved Brief, one worker attempt and the reviews, in 13.5 minutes. Its docs step ran out of the tool-call allowance, one call per turn at the time, just before it wrote, which is why a turn now allows three; that session had also read Foundry's own source and database while looking for context, which sessions of every coding agent can do: the guard refuses the boundary's actions, not reads outside the workspace. Two Foundry sessions in one folder run each other's guards; a guard only denies, so the stricter policy wins. Read-only roles are enforced on the file tools only: a shell write slips past the guard, where Codex has an operating-system sandbox (agy's `--sandbox` is undocumented in its effect and is not used). The CLI's known defects, an empty SUCCESS and a dropped stream, become failed sessions the attempt loop retries. Not seen yet is what agy reports when a group's quota runs out; until it is, such a session fails like any other instead of pausing the provider as a Claude or Codex rate limit does.
